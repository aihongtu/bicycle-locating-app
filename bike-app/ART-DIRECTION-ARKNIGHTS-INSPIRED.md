# 自行车定位助手：舟系工业科幻视觉提示词手册

> 用途：为现有“自行车定位助手”形成原创的工业科幻世界观 UI。目标是借鉴用户提供的《明日方舟》界面参考中可迁移的设计语言，不复制游戏角色、Logo、专属图标、素材、文案或一比一布局。本文件只提供设计方向和生成提示词，不代表已修改现有 app。

## 1. 视觉研究结论

从参考截图中可观察到的风格，不是简单的“黑底荧光绿科幻风”，而是一套内容与界面相互支撑的视觉叙事：

- **世界观场景先行**：主界面以具有真实质感的环境、建筑、天气或人物构成大画面；功能面板覆盖其上，像设备终端在读取现场信息。
- **信息面板像任务终端**：大面积炭黑、烟灰或乳白的矩形面板，边缘硬朗；部分面板半透明，能看到下方环境纹理，但正文仍保持清晰对比。
- **层级靠尺寸和位置，而非一堆圆角卡片**：超大标题和数字、横向功能区、局部编号、细线、短刻度、方向标记共同形成秩序；重要入口可以不对称地错落分布。
- **几何图形有信息语义**：圆环、刻度、三角、菱形、短线、网格、信号条看起来像坐标、状态或组织识别符号，而不是随机贴花。
- **颜色克制，状态色醒目**：黑白灰是结构底色；酸性黄绿、青色、红色、黄色只在特定区块、进度、警告或选中状态出现。颜色需有语义，不能每个组件都发光。
- **字体有明显尺度对比**：标题和核心数值大，辅助标签小而紧凑；中英文字、编号、缩写可形成终端铭牌感。中文功能正文仍需易读。
- **氛围是“严肃的现实 + 一点奇异感”**：材质、地图和环境相对可信，界面叠加少量大胆图形与信号色；不是全屏霓虹、游戏 HUD 堆叠或纯装饰科技纹理。
- **图像和控件各有职责**：人物/场景视觉负责情绪，操作面板负责任务。按钮即使个性化，也要让用户一眼知道它做什么。

Hypergryph 团队在公开采访里将其视觉目标描述为让世界图像同时有现实感与幻想感，并强调 UI 延续既有设计语言的同时要更清晰、更新鲜。对本项目而言，最重要的迁移原则是“有沉浸感，但不能牺牲找车、记录与导航的可读性”。[4Gamer 对 Hypergryph 的采访](https://www.4gamer.net/games/622/G062211/20231207043/)

### 适配本 app 的边界

- 将“作战终端”转译为**城市骑行定位终端 / 车载信标操作台**；将任务进度转译为定位、骑行状态、设备状态和路线数据。
- 视觉可更靠近游戏的工业科幻气质，但不能让老人、学生或通勤者看不懂核心操作。
- 地图必须是主要信息，不要用角色立绘、宣传大图压住地图和按钮。
- 关键中文操作按钮建议不小于 44×44 CSS px；正文至少 14px；只有装饰编号和非关键英文铭牌可以小于 12px。
- 动效说明状态变化，不制造持续闪烁、强烈呼吸、快速扫光或视觉疲劳。
- 本 app 的“模拟设备 / 本地保存 / 模拟骑友”必须诚实标记，不要被写成真实联网或真实蓝牙能力。

## 2. 全局母提示词（四页共用）

```text
请为一款名为“自行车定位助手”的中文手机应用设计一套原创工业科幻界面，核心产品功能是定位自行车、记录骑行、认识附近骑友、管理个人资料。画面采用竖屏手机比例，优先适配 390×844 px，同时考虑 360×780 px；所有正文、状态、按钮要适合真实手机阅读和点击。

视觉方向：以高完成度科幻策略手游中的沉浸式终端 UI 为灵感，但只借鉴抽象的视觉原则，不复刻任何现成游戏画面。将应用设定为“城市骑行行动终端”：可信的街区地图、停车点、路线数据和设备状态是世界观主体。界面采用炭黑/深灰与暖白构成信息面板，使用少量荧光黄绿作为定位/路线/选中状态，青色用于信息状态，琥珀黄用于注意提示，红色用于错误或危险。深浅对比强，文字和地图始终优先可读。

构图采用清楚的栅格和有限的不对称：大标题或核心数字建立主层级，细线、坐标刻度、编号、简洁几何切片、状态条作为系统语言。面板可以有硬朗矩形边缘、局部斜切、细描边或克制透明度；避免整页由相同圆角卡片堆成模板。所有几何装饰必须表达方向、距离、设备状态、数据分组或导航层级，不添加无意义纹理。

字体使用稳健的现代无衬线中文字体；数字采用清晰、略窄的终端风格；英文仅作为微型辅助铭牌，不应取代中文功能文案。图标为同一笔画粗细的原创几何线性图标，禁止用 Emoji 代替功能图标。按钮同时有文字、图标、默认/按下/禁用/成功/错误状态。

保留舒适触控：主要操作按钮至少 44×44 px，文字层级清楚，正文 14–16 px，核心指标 24–34 px。定位地图实际占据页面主视觉。为定位点、路线绘制、卡片进入和按钮反馈加入短促、克制、低干扰的动效；提供静止状态方案，不使用闪烁警报作为常态。

输出高保真 app UI，不要输出设备模型、海报、桌面网页或游戏角色立绘。画面中不出现《明日方舟》、鹰角、罗德岛、干员、游戏 Logo、原作图标、原作专有词、原作版式或可辨认角色。让作品形成自己的“城市骑行终端”身份。
```

## 3. 统一设计系统提示词

```text
请先定义本 app 的原创视觉系统，并让四个 Tab 与所有弹层统一：

1. 色彩 token：炭黑 #171A1B、石墨灰 #262B2C、暖白 #F0F1E9、信号黄绿 #C5E63A、定位青 #33C5D3、提醒琥珀 #F1C84B、错误红 #E14B55、次级灰 #89918D。大面积使用炭黑或暖白；黄绿只给车辆位置、轨迹、当前 Tab 和主操作；青色只表示信息/连接；红色只表示错误/删除/紧急状态。
2. 面板：优先使用大矩形功能面板、细分隔线、局部编号、状态条；圆角只用于头像、地图角、输入控件和少量浮层。通过明暗块面、对齐和字号形成层级，避免所有信息都放在相同的卡片中。
3. 网格：采用 8 px 基准间距。页面标题、内容面板、地图标注及底部导航使用稳定对齐线；允许少数装饰性数据标签错位，不能让按钮位置漂移。
4. 图标：绘制统一的 SVG 几何线图标，包括自行车、定位、发光、响铃、轨迹、暂停、继续、好友、消息、用户、设置、备份、导入、导出、返回、关闭、刷新、放大和缩小。图标尺寸 18–22 px，笔画 1.8–2.2 px；主要操作图标可反白。不要混用系统 Emoji。
5. 字体：中文主标题 22–28 px；次标题 16–18 px；正文/主要按钮 14–16 px；辅助信息 12–13 px；核心数据 24–34 px。英文字段标签可以 9–11 px，但中文正文不能缩成装饰字。
6. 状态语言：在线=黄绿圆点+“在线”；离线=灰点+“离线”；连接中=青色短进度条+文字；定位丢失=琥珀提示条；危险删除=红色按钮并有二次确认；录制中=静止红色状态点和计时器，避免高频闪烁。
7. 反馈：点击后按钮短暂压下，状态改变时配 150–240 ms 位移/透明度过渡；Toast 说明结果；错误与权限问题必须给可理解的文字和下一步操作。
```

## 4. 页面一：找车主界面

### 页面目标

打开 app 后立即回答三件事：**我的车是否在线、车在哪、我能立刻做什么**。车辆地图和距离是一级信息；车辆管理和缩放是二级信息。

### 主界面生成提示词

```text
生成“找车”Tab 的高保真竖屏界面。页面上方为简洁终端状态区：左侧显示产品代号/当前模块编号“01 — LOCATE”，下一行中文大标题“找车”；右侧显示定位状态和一个低调的头像入口。标题下方显示车辆状态条，内容包括车辆名称“我的通勤车”、在线/离线状态、最后定位时间、蓝牙连接状态（若适用），用短横线、微型刻度和状态色表达，不要做成大圆角胶囊。

页面中部让真实地图占据约 50–58% 的可视高度。地图保持道路和街区可辨认，避免复杂底图与文字标注互相干扰。地图上清晰显示“我在这里”的蓝色定位点、自行车信标的黄绿色标记、用户到车辆的方向线/步行路线，以及大号距离“180 m”和估算步行时间。车辆定位点周围有低频、短幅的单次脉冲环；路线进入页面时沿路径绘制完成。右上角放置紧凑的定位/刷新/缩放控制，左下角提供图例或比例尺。标记文字使用深色实底或白色高对比底，不能直接压在复杂道路上。

地图下方展示两个明确主按钮：“发光找车”和“响铃”，使用原创图标、黄绿主按钮和深色次按钮。按钮至少 48 px 高，文字不只靠颜色表达功能。其下方用一行辅助文案说明设备控制结果或设备为模拟模式。页面下缘可有车辆信息、停放时间和“步行导航”入口。

整体像可信的城市定位终端：地图是真正的功能主体，界面面板像设备读数层；允许细刻度、坐标短码、分区编号和一条小型信号谱线作为装饰，但每个装饰都要靠边、低对比、不能抢过距离和主按钮。禁止全屏游戏 HUD、重叠面板、过多光晕、虚构的任务/等级资源。
```

### 找车按钮/控件逐项提示词

- **“刷新位置”**：图标为两段式环形箭头；点击时显示短暂的旋转反馈，文字改为“正在更新…”，返回后标注最后更新时间；失败时显示“位置暂不可用”和重试入口。不要只做一个没有文字的装饰圆钮。
- **“定位车 / 回到车辆”**：靶心/信标图标。点击后地图平滑居中到车的位置，同时保留“我”的位置和距离线；反馈“已定位到车辆”。它与系统定位权限按钮要视觉区分。
- **“＋ / － 缩放”**：同组方形按钮，细分隔线，至少 40 px 点击区；禁用态需低对比但文字仍可辨。
- **“发光找车”**：黄绿实心主操作，灯束/信号图标；按下后信标点出现有限时亮灯边缘并有一次扩散环，状态回到默认时不留永久光晕。模拟设备文案明确“已模拟亮灯 8 秒”；真实连接时才显示“已向设备发送”。
- **“响铃”**：炭黑或浅色描边次操作，铃铛声波图标；点击时出现 3 次短幅声波动效，之后停止；Toast 明确“已模拟响铃 3 次”或真实设备已发送。
- **“车辆管理”**：细线齿轮/车架图标，打开侧向或底部终端面板；信息分区显示当前车辆、连接方式、在线状态、停放时间。不要直接跳到与地图完全不同的风格。
- **“寻找并连接设备”**：用扫描扇区/蓝牙波形表示扫描，展示步骤“扫描附近设备 → 选择设备 → 确认为我的车”；扫描中必须有文字说明，允许取消。扫描列表每行给设备名、信号强度、连接按钮。连接成功后显示绿色状态变化；失败时提供重试。
- **“添加车辆 / 删除车辆 / 断开蓝牙”**：添加用描边按钮；断开用中性按钮并在断开后更新离线状态；删除使用红色危险操作，二次确认明确说明会删除本地车辆记录，不让红色作为日常强调色。
- **地图车辆标记**：自创信标形状，不使用游戏 logo 或单位徽记；外圈方向刻度指向车位；车名、距离有独立标签。没有车辆时显示空地图+明确的“连接或添加车辆”入口，不显示虚构定位。

### 车辆信息卡弹层

```text
设计车辆信息浮层，沿用找车页的炭黑/暖白面板语言。上方显示车名和在线状态；中段以大号距离为焦点，下面列出停放时间、最后更新时间、位置描述、连接类型；底部排列“发光”“响铃”“步行导航”三个操作，主操作步行导航用黄绿强调，发光/响铃使用深色次按钮。弹层保持地图仍隐约可见，但底层压暗以保证文字对比。关闭使用清晰的 X 图标并支持点遮罩关闭；不要做大面积模糊玻璃。
```

### 步行导航界面/状态

```text
设计简洁步行导航状态页：顶部显示“前往车辆”与目标车名；地图占主要面积，用高对比路径、当前位置箭头、车辆终点信标和剩余距离构成核心信息。底部固定导航读数条：当前方向（如“直行”）、剩余距离、下一转向提示；“我已到达”作为宽主按钮，“结束导航/返回”作为次入口。方向箭头可轻微转向过渡，路线只做短暂绘制，不做持续扫光。到达后显示明确成功状态和“已到达车辆附近”。
```

## 5. 页面二：骑行记录

### 页面目标

让用户快速知道今天骑了多少、当前是否记录中、路线在哪里；并能回看历史和路段数据。

### 页面提示词

```text
生成“骑行”Tab 的完整竖屏高保真界面。顶端显示模块编号“02 — RIDE DATA”、大标题“骑行记录”和日期/记录状态。首屏上方为一组紧凑但清楚的核心指标：里程、时长、均速、卡路里。里程和时长稍大，数字使用高对比终端数字；单位与标签必须清楚，不要用图标替代中文标签。指标以分区面板或数据网格呈现，不要四个浮夸渐变大卡。

中部显示骑行地图和真实 GPS 路线。路线按配速着色：低于 3 分钟/公里为黄、3–9 分钟为绿、大于 9 分钟为红；地图上需有图例，并有起点/终点标记。路线细而清楚，点击路段可高亮该段并打开详情。模拟地图或定位失败时用对应说明，不伪装真实 GPS。

正在记录状态显示固定但不过度醒目的录制栏：稳定红点、已记录时长、GPS 状态、暂停/继续、结束并保存；暂停后显示“已暂停”和“继续记录”。未开始时提供单一主按钮“开始记录”，说明会使用 GPS。页面下方显示今日/历史记录列表，日期、距离、时长、均速可快速扫读；空状态有一条解释和开始记录入口。

视觉保持终端数据感：采用坐标网格、经纬小字、分段标尺和细折线作为信息辅助。不要用装饰性的赛博光线替代清晰路径；颜色必须与配速图例一致。
```

### 骑行按钮和功能提示词

- **“开始记录”**：黄色绿主按钮，定位箭头或记录圆点图标；点击前说明将请求 GPS；等待定位时显示“正在获取定位”，权限拒绝时展示解释和系统设置建议，不把失败伪装成录制中。
- **“暂停 / 继续”**：同一位置状态切换；暂停图标为双竖线，继续为三角播放；暂停时停止累计轨迹，不继续显示“正在记录”。恢复时显示“GPS 已恢复/等待定位”。
- **“结束并保存”**：红色次级危险操作，打开确认面板列出本次距离、时长、轨迹点；用户确认后保存。结束后给完成状态和本次总结；点数不足时说明没有生成有效轨迹。
- **“定位”**：地图定位控件，回到当前 GPS 点或已选骑行的起点，并告知当前展示的是哪一条轨迹。
- **地图“＋ / －”**：与找车页面共用的方形缩放按钮样式。
- **历史记录条目**：日期为小标签，距离大于时长/均速；选中态用黄绿短边线/底色变化，不整行荧光发光。选中历史路线后，顶部摘要和地图同步切换。
- **路段点击**：只高亮当前路段；弹出“路段详情”面板，清晰显示里程、均速、用时、配速和对应颜色；关闭回到原地图缩放位置。

### 骑行空状态/异常状态

```text
为骑行记录设计空状态、GPS 权限被拒绝、GPS 信号丢失、记录暂停、保存成功、记录点不足等状态。每个状态都有一个准确的短标题、一句解释、一个可行动作。用图形信号条或定位十字表现状态，不使用大面积插画遮挡功能。定位丢失显示琥珀色提示，保存成功使用黄绿校验符号，权限拒绝提供“查看定位设置”提示。
```

## 6. 页面三：骑友、好友请求与聊天

### 页面目标

区分“附近的人”“已建立好友关系”“收到的申请”，让加好友、接受/忽略和聊天状态一目了然；不把本地模拟骑友伪装成真实在线用户。

### 骑友列表提示词

```text
生成“骑友”Tab 的社交列表界面。顶部显示模块编号“03 — RIDER NETWORK”、标题“骑友”和简短的本地/共享位置状态。下方用三个直观的横向分段入口切换“附近的人 / 好友 / 好友请求”，当前项用黄绿底条、边线或小型几何标记强调；请求数量用小红/琥珀角标，不用大型气泡。

列表使用横向条目而不是重复厚重卡片：左侧圆形头像/自选头像，中间昵称、擦肩时间、当时距离或关系状态，右侧为“加好友”“请求已发送”“同意/忽略”“聊天”等明确动作。每行分隔清楚，点击范围至少 44 px。附近列表注明“今天擦肩”“距你约 X 米”；好友列表显示“好友 X/100”；请求列表明确对方申请。使用同一套头像框、名称字号和状态标签。

当前版本骑友为本地模拟数据时，页面底部以低干扰信息条说明“当前显示模拟骑友，数据保存在本机”，不要画出实时通讯、真实定位在线等虚假信号。空列表显示无数据原因和对应去向按钮。
```

### 细分功能提示词

- **“附近的人 / 好友 / 好友请求”分段导航**：三个等宽选项，选中态用黄绿线和小型编号，不移动整块大面板；切换内容有 160ms 淡入/短位移。
- **“＋加好友”**：明确的文字按钮；点击后变成“请求已发送”，禁用重复提交；Toast 说明已发出并等待处理。状态标签用琥珀/蓝灰，不使用成功绿色假装对方已经同意。
- **“同意 / 忽略”**：同意使用黄绿实色小按钮，忽略使用描边中性按钮；操作后请求从列表移除并出现简洁结果反馈。
- **“删除好友”**：放在好友详情或次级菜单内，默认不要在每行突出红色；确认面板说明删除后关系变化。避免误触。
- **“聊天”列表行**：显示头像、昵称、最后一条消息和时间；进入聊天后显示清晰的返回/对方名称、聊天记录和输入框。
- **聊天输入和发送**：输入框对比充分，发送按钮明确可见；Enter 可发送；对话气泡以深色/亮色区分自己与对方，保证文字反差；模拟自动回复需要显示为演示数据或本地模拟。
- **好友上限**：好友页标题旁显示“X / 100”，达到上限时“加好友”操作进入禁用状态并解释原因。

## 7. 页面四：我的、资料、登录、数据管理

### 个人页提示词

```text
生成“我的”Tab。顶部显示模块编号“04 — PROFILE”、标题“我的终端档案”和低调的设置入口。资料区域展示用户头像、昵称、性别/生日/兴趣/简介中的已填写内容；头像和昵称有清楚主次，不做大型角色立绘。下面显示少量骑行摘要，如累计里程、骑行次数、好友数；这些数字仅使用真实本地数据。

功能入口采用带小图标的水平条目：个人资料、我的车辆、骑行记录、隐私与定位、数据备份与恢复、登录方式。每一行高度至少 48 px，有右侧箭头表示可进入。条目可使用编号和细分隔线形成终端目录感，但不能出现无意义的“任务”“仓库”等游戏化术语。

登录卡片明确显示“游客访问”或“微信用户”；本地模拟微信登录要标注“本地演示”，不要显示真实授权成功的虚假视觉。备份/恢复单独分组，导出和导入按钮区分清楚，导入恢复须有替换数据的确认说明。
```

### 编辑资料提示词

```text
设计个人资料编辑表单。标题“编辑资料”，顶部有返回按钮和保存状态。字段按顺序展示：头像（预设头像网格 + 上传本地图片）、用户名、性别（男/女/保密）、生日、爱好、简介。表单标签固定、输入边界清晰，键盘聚焦态使用黄绿细边线；选择器有明显选中标记。预设头像使用本 app 原创、简洁的抽象骑行标记或用户上传内容，不复制游戏角色。保存是唯一主按钮；取消为次按钮；保存成功给确认反馈。输入错误时在字段下说明，不仅改变边框颜色。
```

### 登录与备份弹层提示词

```text
设计登录与数据管理面板，沿用终端面板和几何分割线：游客/微信登录方式状态、模拟授权说明、授权/取消按钮；备份恢复显示本地存储说明、最近备份状态、导出 JSON、导入文件两个操作。文件选择、恢复确认、导入成功/失败分别有独立状态。红色只用于“覆盖/恢复可能替换当前数据”的风险提示，不用于普通导入按钮。保证隐私说明易读且不过度压缩。
```

## 8. 共用弹层、Toast、状态按钮提示词

### 通用弹层

```text
弹层像终端子面板从主界面上浮或侧向进入，时长 180–240 ms；下方页面仍可辨认但压暗。使用标题、内容、操作区三段式结构，优先保留底层场景，不用强烈背景模糊。每个弹层有明确关闭/返回入口，手机小屏下内容可滚动，主按钮不会被键盘或底部导航遮挡。
```

### Toast

```text
Toast 位于屏幕安全区内，使用高对比炭黑底/暖白字或暖白底/深字，显示明确结果，如“已模拟亮灯 8 秒”“记录已暂停”“好友请求已发送”“备份导入失败：文件格式不正确”。持续 1.5–2.2 秒；错误和必须处理的警告改用页面内提示条，不能只靠一闪而过的 Toast。
```

### 按钮状态总规范

```text
为每个按钮生成五种状态：默认、按下、处理中、禁用、成功/错误。按下时轻微缩小到 98% 或边线内移；处理中显示短状态文字和低速进度，不播放无限循环霓虹；禁用态降低填充对比但正文仍达到可读对比；成功态用一个短脉冲/勾形标记，不持续闪烁。危险操作用红色并要求二次确认。所有按钮必须有文字标签或可访问名称，不允许只用抽象符号。
```

## 9. 动效提示词（克制且有功能含义）

```text
动效系统采用“终端启动，但服务于真实信息”的原则：
- 页面切换：内容淡入并上移 4–8 px，160–220 ms；底部当前 Tab 的细条平滑移动。
- 地图路线：首次出现时沿路径绘制 500–900 ms；更新位置时用 1 次轻脉冲指出新信标位置。
- 车辆信标：在线时不持续发光；每隔较长时间做一次柔和扩散环，或者仅在刷新/发光操作成功后播放。
- GPS 记录：用固定红点+计时，不快速闪烁；暂停时停止计时动画；结束后路线折线短暂完成绘制。
- 列表：新请求出现时只轻微高亮对应行；聊天新消息从下方淡入，不弹跳。
- 按钮：响应快、反馈短，不做弹性过度、旋转大圈或视差。
- 支持 prefers-reduced-motion；用户开启减少动态效果后，所有循环动画停止，只保留状态变化所需的即时反馈。
```

## 10. 负面提示词 / 禁止项

```text
不要复制明日方舟的具体页面布局、Logo、罗德岛标志、干员形象、角色剪影、游戏内英文标题、专属三角徽记、原作状态图标、截图或活动 KV。不要出现不存在的游戏货币、等级、招募、任务、仓库等元素。不要把界面做成电竞 HUD、军事瞄准镜、全屏荧光绿色或满屏扫描线。不要将地图当成模糊背景。不要使用十几种高饱和色、厚重玻璃拟态、过多发光描边、随机三角碎片、装饰性英文乱码、无意义坐标、过小中文、低对比灰字、不可点击的小图标、重复圆角卡片。不要虚构 GPS 正在记录、蓝牙已连接、真实好友在线或云端同步状态。不要让任何动效遮住文字、路线、距离和操作按钮。
```

## 11. 推荐的生成/设计顺序

1. **先生成找车页主视觉**：验证地图、车辆信标、距离读数、发光/响铃两个主操作的层级。不要先把四页都堆满装饰。
2. **建立组件页**：车辆状态条、状态色、数据面板、地图标记、按钮五态、Toast、弹层、列表项、表单字段。
3. **扩展到骑行页**：重点校验配速图例、记录状态、暂停/继续与历史列表是否读得懂。
4. **扩展到骑友页和我的页**：维持系统一致，但按社交列表和表单调整信息密度。
5. **检查边界状态**：无车、离线、GPS 拒绝、GPS 丢失、暂停、无骑友、请求待处理、没有历史、导入失败。
6. **最后加装饰与动效**：每个装饰要能回答“它传达了什么”；如果不能传达方向、状态、层级或品牌信息，就删除。

**“把自行车定位助手设计成一台属于城市骑行者的行动终端：真实街区地图是现场，车辆信标和路线数据是任务信息，面板和信号色是设备语言；氛围沉浸而克制，操作仍一眼可懂。”**
